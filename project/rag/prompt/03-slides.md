请根据 `README.md` 和 `case/` 目录下的案例代码，在 `slides/` 目录下生成一套 Typst 课件，面向本科生教学。必须严格按以下工作流执行，不得跳过编译验证环节：

## 工作流

1. **编写内容**：仅修改 `slides/section.typ`（参考其中的示例样式），不要新建其他文件，不要修改 `slides/main.typ`
2. **编译验证**：在 `slides/` 目录内执行 `make`（无其他参数），目录下已有 `Makefile` 配置文件
3. **视觉校验**：执行 `mkdir -p .cache && pdftoppm -png -r 96 main.pdf .cache/page` 将每页渲染成图片，再用 read 工具逐页查看，检查内容溢出、遮挡与截断、字体缺失（豆腐块）、错别字、页面太空或过挤、代码排版等视觉问题
4. **修复重试**：若编译失败或视觉校验发现问题，修正 `slides/section.typ` 后重新执行步骤 2、3，直至编译通过且所有页面无明显问题

所有文件读写和命令执行均以 `slides/` 目录为工作目录，禁止在 `slides/` 上级目录执行 `make`。

## 内容规范

- `README.md` 为教师讲义，教师备课参考用，部分不方便展示给学生的内容可以不放在课件中，比如“时间分配“、“课堂互动”等
- `slides/section.typ` 仅供参考 typst 语法，最后的排版、结构、语气等自主规划即可
- 内容详尽、结构清晰，适合授课及零基础自学；每页代码均需附带详细讲解，不可单独放置代码
- 页面要充实：除封面、目录、章节标题页、结束页等结构性页面外，每页都要有实质内容，避免只有一两行字或大段空白；要点不能只是标题的罗列，应给出必要的解释、示例、公式或对比
- 排版元素要用足：列表、表格、代码块、图示等按内容需要合理使用，提升信息密度与可读性，但不要为填满页面而生硬堆砌
- 课件中的代码示例优先引用 `case/` 目录下的案例代码，保持理论与实战结合
- 课件中出现的命令与依赖必须与案例一致：环境相关只出现 `uv add` / `uv run`（禁止 pip install、手工编辑 pyproject.toml 等步骤），模型统一 `deepseek-flash`，密钥通过 `OPENAI_BASE_URL` / `OPENAI_API_KEY` 环境变量读取
- 使用 `= XXX` 一级标题和 `== XXX` 二级标题组织章节，一级标题的数量要尽可能克制，最少 $page 页
- 标题禁用 A 与 B 式并列结构，此类结构易显机械且导致主题分散
- 去 AI 味：课件正文避免使用破折号（——）、引号、括号、箭头（→、->）、单横杠等非必要符号（对话的引号可以保留，代码、命令、列表标记等其他特殊情形也可以酌情保留）
- 不布置作业、课后练习或思考题
- 不出现课时时长、时间分配、课时序号等课程元信息
- 课件必须自成体系，单独使用即可授课：不出现指向其他课时的内容或引用，不假设学生学过其他课时
